# Локальный просмотр Chicago Pizza

Стенд работает через Docker Compose. Docker Desktop должен оставаться запущенным.

- Сайт: http://localhost
- Меню напитков: http://localhost/menu?category=drinks
- Регистрация: http://localhost/register
- Тестовая почта: http://localhost:8025
- Панель администратора: http://localhost/admin

Если локальная база была заполнена с `SEED_DEMO_ACCOUNTS=true`, тестовый администратор:
`admin@chicago-pizza.ru` / `Admin123!`. Эти данные предназначены только для демо-стенда;
рабочий администратор опубликованного сайта создавался отдельно.

Для проверки регистрации используйте новый email: письмо с шестизначным кодом появится в MailHog, а не в настоящем почтовом ящике. Подтвердите email, войдите, добавьте товары и оформите заказ с оплатой при получении. Онлайн-кнопка видна, но без реквизитов ЮKassa недоступна. Подключение тестового магазина и чеков описано в [PAYMENTS_YOOKASSA.md](PAYMENTS_YOOKASSA.md). Вне часов работы выберите «Ко времени» и подходящий слот.

Для ручного просмотра проверьте маску телефона на регистрации, выбор вкусов Kinza,
корзину, оформление и удаление адреса. Миграции применяет контейнер `migrate`.
Подробная проверка мобильного интерфейса — [MOBILE_CHECKLIST.md](MOBILE_CHECKLIST.md).
Исторические тестовые заказы могут оставаться в локальной базе; её фактическое состояние
нужно проверять, а не принимать результаты старого прогона за текущие.

Чтобы снова запустить уже собранные контейнеры из корня проекта:

```powershell
docker compose --profile dev up -d --no-build
```

Остановить их с сохранением данных:

```powershell
docker compose --profile dev stop
```

Не используйте `down -v`: это удалит локальные данные.

Повторная сквозная проверка из каталога `client` (создаёт тестового покупателя и локальный заказ):

```powershell
$env:E2E_BASE_URL = 'http://localhost'
$env:MAILHOG_URL = 'http://localhost:8025'
npx playwright test e2e/local-registration.spec.ts --project=chromium --no-deps --workers=1
```

Полный прогон каталога требует повышенных лимитов на отдельном тестовом стенде,
как в CI; пользовательский просмотр работает со штатными лимитами. Результаты длительной
нагрузки находятся в [LOAD_TEST_REPORT.md](LOAD_TEST_REPORT.md), а не в этой инструкции запуска.
