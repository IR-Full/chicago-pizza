# Локальный просмотр Chicago Pizza

Стенд работает через Docker Compose. Docker Desktop должен оставаться запущенным.

- Сайт: http://localhost
- Меню напитков: http://localhost/menu?category=drinks
- Регистрация: http://localhost/register
- Тестовая почта: http://localhost:8025
- Панель администратора: http://localhost/admin

Тестовый администратор: `admin@chicago-pizza.ru` / `Admin123!`. Эти данные предназначены только для локального стенда.

Для проверки регистрации используйте новый email: письмо с шестизначным кодом появится в MailHog, а не в настоящем почтовом ящике. Подтвердите email, войдите, добавьте товары и оформите заказ с оплатой при получении. Онлайн-оплата без реквизитов ЮKassa отключена. Вне часов работы выберите «Ко времени» и подходящий слот.

Kinza остаётся одной карточкой со значком 🥤 и шестью вкусами: Кола, Апельсин, Цитрус, Чёрная смородина, Гранат, Лимон. Фото показываются только после выбора вкуса. Названия двух вкусов исправлены по согласованию с владельцем; идентификаторы вариантов и история заказов сохранены. У остальных напитков и снеков без исходных фотографий остаются обозначения соответствующей категории. Описание Колы — «железная банка», метка «Новинки» красная.

На узких экранах вкладки админки остаются одной строкой с горизонтальной прокруткой. При выборе обращения страница переходит к чату; список обращений прокручивается отдельно. Повторная отправка одного ответа защищена ключом попытки и блокировкой на сервере; одинаковый ответ того же автора подряд в течение 30 секунд не создаёт вторую запись. Повреждённые старые тексты не переписаны: вместо символов `�` интерфейс объясняет, что исходный текст утрачен. Новые русскоязычные сообщения проверены через настоящий API.

В локальной базе сохранены тестовые заказы с комментарием `LOCAL CATALOG VERIFICATION — test order`. Они не являются реальными заказами. Перед обновлением базы сохранён дамп `server/.verification/before-catalog-verification.dump`; он исключён из Git и Docker build context.

Чтобы снова запустить уже собранные контейнеры из корня проекта:

```powershell
docker compose --profile dev up -d --no-build
```

Остановить их с сохранением данных:

```powershell
docker compose --profile dev stop
```

Не используйте `down -v`: это удалит локальные данные.

Повторная сквозная проверка из каталога `client` (создаёт тестового покупателя и локальный заказ):

```powershell
$env:E2E_BASE_URL = 'http://localhost'
$env:MAILHOG_URL = 'http://localhost:8025'
npx playwright test e2e/local-registration.spec.ts --project=chromium --no-deps --workers=1
```

Полный прогон каталога требует повышенных локальных лимитов, как в CI; пользовательский просмотр работает со штатными лимитами. Проверены 32 карточки, 77 конфигураций цены, добавление 37 различных позиций с учётом вкусов Kinza, регистрация с подтверждением email, перенос гостевой корзины и сохранение вкусов в заказе. Отдельно проверено живое уведомление через WebSocket.
